# Contributing Guidelines / Panduan Kontribusi

Thanks for helping improve **Awesome Cybersecurity Resources**! / Terima kasih sudah ikut memperbaiki list ini!

---

## English

### What belongs here

- Tools, platforms, and learning material relevant to **network security, penetration testing, and blue team / defensive security**.
- Resources that are **real, reachable, and reasonably maintained**. Dead links and abandoned projects will be rejected or removed.
- One resource per line.

### What does not belong here

- Broken, paywalled-without-value, or login-walled resources with no useful public content.
- Duplicate entries, or the same project listed in more than two sections.
- Low-effort blogspam, affiliate link farms, or SEO pages.

### Formatting rules

1. Each entry uses exactly this format:
   ```
   - [Resource Name](https://example.com) - One-line description that ends with a period.
   ```
2. Use HTTPS URLs where available. No tracking parameters, no URL shorteners.
3. Descriptions are a **single line**, start with a capital letter, end with a period, and describe what the resource *is* or *does* — not marketing copy.
4. Keep descriptions short (aim for under 100 characters).
5. Entries within a section must be ordered so the most essential / widely used tools come first, then remaining entries **alphabetically**. If unsure, alphabetical is always safe.
6. Add new sections only if a resource genuinely does not fit an existing one — open an issue to discuss first.
7. Update the **Table of Contents** if you add or rename a section.

### Self-promotion

You may submit a project you created or maintain, but:

- Disclose it in the pull request description.
- It must meet the same quality bar as everything else.
- Do not submit more than one of your own projects in a single PR, and do not stuff one project into multiple sections.

### Submitting a pull request

1. Fork the repository and create a branch: `git checkout -b add-resource-name`.
2. Make your change in `README.md`.
3. Confirm your links work and the format matches the rules above.
4. Commit with a clear message: `Add <Resource Name> to <Section>`.
5. Open a pull request. In the description, briefly explain why the resource is worth adding.
6. One logical change per pull request. Batching many unrelated additions makes review slow.

### Removing a resource

If a resource is dead, unmaintained, or no longer relevant, open a PR or issue explaining what changed. Removals are just as valuable as additions.

## Bahasa Indonesia

### Yang boleh masuk

- Tools, platform, dan materi belajar yang relevan dengan **keamanan jaringan, penetration testing, dan blue team / defensive security**.
- Resource yang **nyata, bisa diakses, dan masih dirawat**. Link mati dan proyek yang ditinggalkan akan ditolak atau dihapus.
- Satu resource per baris.

### Yang tidak boleh masuk

- Link rusak, halaman berbayar tanpa nilai, atau yang terkunci login tanpa konten publik yang berguna.
- Entri duplikat, atau proyek yang sama muncul di lebih dari dua section.
- Blogspam, halaman affiliate, atau halaman SEO berkualitas rendah.

### Aturan format

1. Setiap entri memakai format persis seperti ini:
   ```
   - [Nama Resource](https://example.com) - Deskripsi satu baris yang diakhiri titik.
   ```
2. Gunakan URL HTTPS bila tersedia. Tanpa parameter tracking, tanpa URL shortener.
3. Deskripsi **satu baris**, diawali huruf kapital, diakhiri titik, dan menjelaskan resource itu *apa* / *fungsinya apa* — bukan bahasa promosi.
4. Deskripsi singkat (usahakan di bawah 100 karakter).
5. Urutan entri dalam satu section: tool paling penting / paling umum dipakai duluan, sisanya **berurutan alfabetis**. Kalau ragu, alfabetis selalu aman.
6. Tambah section baru hanya kalau resource benar-benar tidak cocok di section mana pun — buka issue dulu untuk diskusi.
7. Perbarui **Table of Contents** kalau kamu menamb/mengganti nama section.

### Promosi diri

Kamu boleh mengusulkan proyek buatanmu sendiri, tapi:

- Sebutkan hal itu di deskripsi pull request.
- Kualitasnya harus setara dengan entri lain.
- Jangan kirim lebih dari satu proyek milikmu dalam satu PR, dan jangan menaruh satu proyek di banyak section.

### Cara mengirim pull request

1. Fork repo, buat branch: `git checkout -b add-nama-resource`.
2. Lakukan perubahan di `README.md`.
3. Pastikan link berfungsi dan formatnya sesuai aturan di atas.
4. Commit dengan pesan jelas: `Add <Nama Resource> to <Section>`.
5. Buka pull request. Di deskripsi, jelaskan singkat kenapa resource ini layak ditambah.
6. Satu perubahan logis per pull request.

### Menghapus resource

Kalau ada resource yang mati, tidak dirawat, atau sudah tidak relevan, buka PR atau issue yang menjelaskan apa yang berubah. Penghapusan sama berharganya dengan penambahan.
